# Orchestration Checklist

## Before implementation
- What business value exists?
- Which module owns it?
- What is in/out?
- Which risks matter first?
- What must be testable later?

## After implementation
Produce a **Tester Orientation Pack**:
1. what was built,
2. key modules/classes/pages,
3. API/database/auth effects,
4. what could break,
5. what to test at each level,
6. parallel/data concerns,
7. Obsidian notes to create.
