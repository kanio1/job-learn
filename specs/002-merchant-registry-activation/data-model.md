# Data Model: Phase 1 — Merchant Registry

**Date**: 2026-05-18 | **Spec**: [spec.md](./spec.md)

## Entity: Merchant

### PostgreSQL Table: `merchants`

| Column | Type | Constraints | Description |
|---|---|---|---|
| `merchant_id` | `UUID` | `PRIMARY KEY`, `NOT NULL`, generated by application | Internal system identifier |
| `normalized_reference` | `VARCHAR(64)` | `UNIQUE`, `NOT NULL` | Uppercase, trimmed merchant reference (e.g., `MERCH-001`) |
| `display_name` | `VARCHAR(120)` | `NOT NULL` | Human-readable merchant name, stored trimmed |
| `status` | `VARCHAR(20)` | `NOT NULL`, `CHECK (status IN ('DRAFT','ACTIVE','SUSPENDED'))` | Lifecycle state |
| `created_at` | `TIMESTAMPTZ` | `NOT NULL`, `DEFAULT NOW()` | Record creation time |
| `updated_at` | `TIMESTAMPTZ` | `NOT NULL`, `DEFAULT NOW()` | Last modification time |
| `version` | `BIGINT` | `NOT NULL`, `DEFAULT 0` | Optimistic locking version |

### Indexes

| Index | Columns | Purpose |
|---|---|---|
| `idx_merchants_status` | `status` | Filter by lifecycle state (future eligibility queries) |
| `idx_merchants_created_at` | `created_at DESC, merchant_id ASC` | Stable newest-first list ordering with deterministic tie-breaker per FR-018 |

### Flyway Migration

```sql
-- V1__create_merchants.sql
CREATE TABLE merchants (
    merchant_id         UUID PRIMARY KEY,
    normalized_reference VARCHAR(64) NOT NULL,
    display_name        VARCHAR(120) NOT NULL,
    status              VARCHAR(20) NOT NULL DEFAULT 'DRAFT',
    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    version             BIGINT NOT NULL DEFAULT 0,
    CONSTRAINT chk_merchants_status CHECK (status IN ('DRAFT', 'ACTIVE', 'SUSPENDED')),
    CONSTRAINT uk_merchants_normalized_reference UNIQUE (normalized_reference)
);

CREATE INDEX idx_merchants_status ON merchants (status);
CREATE INDEX idx_merchants_created_at ON merchants (created_at DESC, merchant_id ASC);
```

### Design Notes

- **`merchantId` is generated by the application**, not the database. This ensures the ID is available immediately after creation for the API response without a database round-trip.
- **`normalized_reference` stores the uppercase form.** The raw input from the API is trimmed and uppercased by the domain layer before persistence. This single column covers both the unique constraint and the normalized identity.
- **`merchantReference` is not stored in raw form.** The raw input is used only transiently during creation. All reads return the normalized form. This avoids confusion between raw and normalized values in the API.
- **`version` column for optimistic locking.** If two requests attempt to create a merchant with the same reference near-simultaneously, the unique constraint on `normalized_reference` catches the duplicate. `@Version` handles concurrent updates to the same row.
- **No `merchant_reference` column with original case.** The spec treats the normalized form as canonical. If future phases need original-case display, a separate column can be added.
- **`updated_at` changes on lifecycle transitions.** The application layer sets `updated_at` to `now()` when status changes. No database trigger is needed; Hibernate `@UpdateTimestamp` or explicit application-set logic handles this.

## Domain Model: Java Types

### Merchant (JPA Entity)

```java
@Entity
@Table(name = "merchants")
class Merchant {
    @Id
    @Column(name = "merchant_id")
    UUID merchantId;

    @Column(name = "normalized_reference", length = 64, unique = true, nullable = false)
    String normalizedReference;

    @Column(name = "display_name", length = 120, nullable = false)
    String displayName;

    @Enumerated(STRING)
    @Column(name = "status", length = 20, nullable = false)
    MerchantStatus status;

    @Column(name = "created_at", nullable = false, updatable = false)
    Instant createdAt;

    @Column(name = "updated_at", nullable = false)
    Instant updatedAt;

    @Version
    @Column(name = "version")
    Long version;
}
```

### MerchantStatus (Enum)

```java
enum MerchantStatus {
    DRAFT,
    ACTIVE,
    SUSPENDED;

    boolean canTransitionTo(MerchantStatus target) {
        return switch (this) {
            case DRAFT -> target == ACTIVE;
            case ACTIVE -> target == SUSPENDED;
            case SUSPENDED -> false;
        };
    }
}
```

### MerchantReference (Value Object)

```java
record MerchantReference(String normalized) {
    static final Pattern PATTERN = Pattern.compile("^[A-Z0-9][A-Z0-9-]{1,62}[A-Z0-9]$");

    static MerchantReference from(String raw) {
        if (raw == null) {
            throw new InvalidMerchantReferenceException(null);
        }
        String trimmed = raw.trim().toUpperCase(Locale.ROOT);
        if (!PATTERN.matcher(trimmed).matches()) {
            throw new InvalidMerchantReferenceException(trimmed);
        }
        return new MerchantReference(trimmed);
    }
}
```

### DisplayName (Value Object)

```java
record DisplayName(String value) {
    static DisplayName from(String raw) {
        if (raw == null) {
            throw new InvalidDisplayNameException(null);
        }
        String trimmed = raw.trim();
        if (trimmed.length() < 2 || trimmed.length() > 120) {
            throw new InvalidDisplayNameException(trimmed);
        }
        return new DisplayName(trimmed);
    }
}
```

## Relationships

None in Phase 1. Future payment entities will reference `merchant_id` as a foreign key, but this is deferred.
