## Objective and stopping condition

Implement the complete program defined by `.codex/specs/playwright-tests-pom-quality-hardening.md` through tickets `01`–`09` in `.codex/tickets/playwright-tests-pom-quality-hardening/`.

- Allowed: live POM framework, Playwright configs, frontend package scripts, POM documentation, the mutable state file and validation evidence.
- Forbidden without new user authorization: production Vue/Nitro/Spring behavior, backend code/tests, dependency or version changes, `.kiro/**`, learner `My*`/`Lesson*`, `.env`, credentials and generated auth state.
- Preserve the inherited dirty worktree, especially Event Lab. Never revert, reset, clean, overwrite or reformat unrelated work.
- No live-POM network mocks: no `page.route`, `route.fulfill`, HAR or browser-to-broker shortcut.
- No `waitForTimeout`, `test.only`, `as any`, blanket TypeScript suppression or password fallback.
- Passwords come only from environment variables. Never print them or copy storage state into evidence.
- Never retry a mutating UI/API action inside polling. Register the observation, mutate once, then poll/assert the outcome.
- Do not add dependencies, commit or push.
- Do not fix the known unrelated production lint failure. Isolate it and prove the POM scope separately.

## Per-ticket loop

1. **Baseline** — inspect current source and dirty diff; record the focused command and result.
2. **RED** — expose the smallest failing compile/behavior check at the agreed public seam. For a pure refactor, lock behavior first and make the intended static rule fail.
3. **GREEN** — implement the smallest change satisfying the current acceptance ID.
4. **REFACTOR** — only after green; prefer native Playwright/TypeScript and net deletion.
5. **VALIDATE** — single check → affected spec/file → strict POM typecheck → POM-only lint.
6. **VERIFY** — run the appropriate live REST/E2E test when the required stack and env-only credentials exist.
7. **REVIEW** — review the scoped diff against the ticket/spec; resolve in-scope P0/P1.
8. **RECORD** — update only the mutable state and append concise evidence keyed by acceptance ID.

Allowed result labels: `PASS`, `NOT_RUN`, `ENVIRONMENT_FAILURE`, `PRE_EXISTING_OUT_OF_SCOPE`, `IMPLEMENTATION_REGRESSION`, `SUSPECTED_FLAKE`.

4. Main Playwright `--list`.

6. Exact modified live spec/project.
7. All modified journeys.
8. `corepack pnpm typecheck`; run full lint and classify the unchanged unrelated failure if still present.
9. Full main live POM.
10. Event Lab Kafka and required TLS/RLS/Mirror smoke runs with documented stacks.
11. `git diff --check` and final reviews.

Use existing commands/runbooks. Do not create another runner. Check only whether required password variable names exist; never echo values. Starting the documented stack is allowed; editing `.env` or inventing credentials is not.

## Evidence contract

Use exactly `status/evidence/playwright-tests-pom-quality-hardening.md`. Append short dated checkpoints; do not rename the file per run.

Each checkpoint records branch/commit and dirty-worktree note, ticket plus acceptance IDs, exact commands and exit status, discovered/executed/passed/failed/flaky/skipped counts, warning counts before/after, live stack/config, reviews, and every `NOT_RUN`. Never record secrets, tokens, cookies or storage state.

The state file is a short pointer, not a log: current ticket, current acceptance ID, phase, next action, last green gate and blockers. Keep it below 40 lines by replacing old values.
