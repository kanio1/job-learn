# Triage

Move incoming items through a small state machine. **Do not triage tickets that `to-tickets` already marked `ready-for-agent`.**

Tracker: `docs/agents/issue-tracker.md`. Labels: `docs/agents/triage-labels.md`. Briefs: [AGENT-BRIEF.md](AGENT-BRIEF.md).

Every comment appended during triage starts with:

```
> *This was generated by AI during triage.*
```

## Roles

Category (exactly one): `bug` | `enhancement`

State (exactly one): `needs-triage` | `needs-info` | `ready-for-agent` | `ready-for-human` | `wontfix`

## Show what needs attention

Scan `.codex/inbox/` and any ticket whose `Status:` is unlabeled, `needs-triage`, or `needs-info` with new comments. Oldest first. One-line summary each. Let the user pick.

## Triage one item

1. Read the file, comments, `.codex/CONTEXT.md`, ADRs, and `.codex/out-of-scope/`.
2. Check **redundancy** (already implemented → `wontfix`, point at the behaviour, do not write out-of-scope) and **prior rejection**.
3. Recommend category + state. Wait.
4. Verify: reproduce a bug, or confirm a claim. Insufficient detail → `needs-info`.
5. Grill with `grilling` if the request is underspecified.
6. Apply:
   - `ready-for-agent` — append an agent brief; set `Status: ready-for-agent`. Next skill is `implement`.
   - `ready-for-human` — same brief, plus why it cannot be delegated (`wizard` if only a human can click).
   - `needs-info` — established-so-far + specific questions.
   - `wontfix` / rejected enhancement — `.codex/out-of-scope/<concept>.md` then close.
   - Standing lab non-goals → `wontfix` unless the user redraws scope.

## Quick override

If the user says "move this to ready-for-agent", apply it. Ask whether they want a brief if none exists.
