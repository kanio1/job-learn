## 1. Original Kiro intent

Spec #5 (final) of the Playwright/SDET five-spec roadmap, and its capstone enabler. It adds:

- A new `seed` Spring profile that loads a **Deterministic_Dataset** on startup via a profile-gated `SeedRunner` (never a Flyway repeatable migration in the default location, so it can never run in production and never conflicts with `ddl-auto: validate`).
- A **Fixtures_Catalog** of fixed UUID primary keys and natural-key references (3 tenants, 3 merchants, 6+ payment orders across all lifecycle statuses, expanded with a pagination/summary block) documented in `requirements.md`/`design.md` as illustrative-then-finalized.
- Two test-only endpoints, `POST /api/test/reset` and `POST /api/test/seed`, gated by `app.testing.enabled` (default `false`), forced off under `prod`, returning `404` (not `403`) when disabled — bean-absence, not a `403` filter.
- A new dedicated `testing` Spring Modulith module (resolving Open Question 1) that orchestrates seeding/reset purely through each domain module's PUBLIC `*SeedCapability` interface (`TenantSeedCapability`, `MerchantSeedCapability`, `PaymentSeedCapability`, optionally `AuditSeedCapability`), never importing `*.internal.*`.
- Explicit **incremental staging**: Stage 1 (merchants + payments, buildable immediately) → Stage 2 (tenants, after `tenant-model-and-isolation` #2) → Stage 3 (realm-alignment property, after `iam-roles-and-keycloak-login` #1 + `user-management` #3) → Stage 4 (audit, after `audit-log-dashboard` #4, conditional on Open Question 2).
- Six correctness properties (P1 seed idempotency, P2 fixed identities, P3 reset→baseline, P4 prod safety, P5 disabled→404, P6 realm-alignment), most targeted for jqwik property tests (≥100 iterations) except P4/P5 which the design explicitly assigns to integration/example tests instead of PBT.
- Non-goals: no Keycloak realm seeding (alignment only), no production behavior change, no UI, no replacement of the existing per-class Testcontainers + `deleteAll()` isolation pattern, no Playwright files.

All 31 checkbox items in `tasks.md` are unchecked `[ ]` by design — `.kiro/**` is immutable during implementation and does not reflect execution status.

`docs/specs-analysis/07-deterministic-seed-and-test-isolation/README.md` is **stale**: its header still reads "Status: 🔲 Spec gotowa (requirements + design + tasks) — implementacja nierozpoczęta" ("spec ready, implementation not started"). This contradicts the `.codex/current-state.md` record that the spec is `COMPLETED` (Wave 1R/2R/3R). See Section 4 for the flag.
