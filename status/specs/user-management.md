## 1. Original Kiro intent

Spec #3 of the Playwright/SDET roadmap. Adds user management (list, create, view, update, enable/disable, role-assign) to the Payment Quality Engineering Lab as a **façade over the Keycloak Admin REST API** — Keycloak is the single source of truth for identity; the backend holds **no local `app_user` table, no JPA entity, no Flyway migration**. The defining decisions:

- **Decision 1**: Keycloak Admin API façade (not a local user table) — avoids dual-write/sync, teaches realistic identity-administration integration.
- **Decision 2**: only the five existing composite roles (`PLATFORM_ADMIN`, `TENANT_ADMIN`, `MERCHANT_MANAGER`, `SUPPORT_AGENT`, `READ_ONLY_USER`) are assignable — no raw authority roles exposed.

The spec has **two hard prerequisites** (Wave 0 gate): `iam-roles-and-keycloak-login` (Spec #1 — composite roles, `tenant_id` claim, `rbacMatrix.ts`) and `tenant-model-and-isolation` (Spec #2 — `TenantResolver`/`TenantContext`/`TenantReference` PUBLIC API, masked-404/403 isolation pattern). It **extends** (not creates) three cross-spec artifacts: the Keycloak realm import (+8 authority roles, composite aggregation, service-account client), the shared `Authorities` catalog (+8 constants), and the `KeycloakRealmRoleConverter` allowlist (+8 entries, converter rule unchanged).

New backend module `iam` (`lab.paymentquality.iam`, closed, `internal/{web,application,domain,infrastructure}` only, no PUBLIC API) exposes 5 endpoints (`GET/POST /api/users`, `GET/PATCH /api/users/{id}`, `POST /api/users/{id}/roles`) via `KeycloakAdminClient` (thin `RestClient` wrapper, deliberately not the `keycloak-admin-client` library) authenticated by its own service-account client-credentials grant — the admin token never touches the browser or reuses the acting principal's bearer token. Concurrency model: no ETags/`If-Match` on Keycloak Admin API resources; safe-edit re-fetch-before-write with documented last-write-wins risk. Frontend: `/admin/users` page with 7 required UI states, `UserTable`/`CreateUserForm`/`EditUserDrawer`/`RoleAssignmentSelect`, `rbacMatrix.ts` extended with `canManageUsers`/`canAssignRoles` (PLATFORM_ADMIN + TENANT_ADMIN only), role-gated nav link. Six correctness properties (P1–P6) are specified for jqwik/fast-check; two tests are explicitly NON-optional (`IamModuleTest` module-boundary test and Testcontainers-Keycloak integration tests), all other unit/slice/property/component tests are marked optional (`*`). **No Playwright files are created by this spec** — a conceptual Future Playwright Scenarios section records lessons for later.

## 5. Deviations from original design

| Deviation | Classification | Notes |
|---|---|---|
| Keycloak user-profile `attributes` bug during 6.7 | ACCEPTABLE | Keycloak 26.6.1 requires custom attributes (`tenant_id`, `merchant_id`) to be declared in its user-profile configuration or it silently discards them on write. The test helper's original fix attempt inserted the attribute JSON into the wrong array (`groups` instead of the profile's root `attributes` array) via a fragile `lastIndexOf("]")` string edit, causing Keycloak to reject/ignore the profile update. Root cause fixed with structural Jackson-based editing of the correct array. This was an environment/tooling defect in the test harness, not a design flaw, and is fully resolved with 3/3 green IT tests. |
