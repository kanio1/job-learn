## 1. Original Kiro intent

Spec #4 of the Playwright/SDET roadmap: add a **global, searchable, append-only audit log** to the Payment Quality Engineering Lab, exposed read-only via `GET /api/audit` and `GET /api/audit/{id}` and a `/admin/audit` Dashboard page. Audit capture is **event-driven and observational** (Resolved Decision A): a new `audit` Spring Modulith module (package `lab.paymentquality.audit`, no PUBLIC API) owns a real, indexed `audit_event` Postgres table (Resolved Decision C) and an `AuditEventListener` annotated `@ApplicationModuleListener` that consumes a single generic `AuditableActionOccurred` event (declared in `shared.events`, OQ1/Option-A) published by the merchant, payment, and iam/user-management "emitting" modules — the project's **first** use of Spring Modulith application events. The spec introduces a new authority family `platform:audit:read` / `tenant:audit:read` (Resolved Decision B), distinct from the pre-existing `platform:payments:audit`, requiring additive extension of the Keycloak realm, the `Authorities` catalog, and `KeycloakRealmRoleConverter`. Tenant scoping reuses `tenant-model-and-isolation`'s `TenantResolver`/`TenantContext`: platform-scoped principals (PLATFORM_ADMIN, SUPPORT_AGENT) see all tenants; TENANT_ADMIN is confined to its own tenant with cross-tenant single-entry reads masked as `404`. The frontend adds Zod schemas, `useAuditApi`, read-only server proxy routes, a new `canViewAuditLog` RBAC capability (OQ2, distinct from `canReadAudit`), the `/admin/audit` page with `AuditTable`/`AuditFilters`/`AuditEntryDrawer`, native `<input type="date">` filters (Resolved Decision D), a role-gated nav link, and six distinct read-only UI states. Explicitly out of scope: any audit write endpoint, export/CSV, retention/purge policy, and any Playwright test file (conceptual scenarios only). Six correctness properties (P1–P6, jqwik + one fast-check) are defined but their sub-tasks are optional.
