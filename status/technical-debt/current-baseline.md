**Rejected hypothesis:** the audit brief's PENDING-vs-DRAFT merchant-status hypothesis (§16, first bullet) was NOT directly observed in any captured error message — no failure shows a status-text mismatch like "expected ACTIVE, got DRAFT" or similar. The actual failures are all "element not found" (missing heading/text/testid) or timeouts, which points to locator/copy staleness or route changes in a cluster of older spec files, not a PENDING/DRAFT terminology mismatch. This hypothesis is **not confirmed by this session's evidence** — a deeper diff of the actual rendered page HTML against each stale spec file would be needed to fully reject it, which was out of scope for this audit (no fixing, no browser-driving beyond the automated Playwright run itself).

**Not independently re-verified with PostgreSQL/Testcontainers this session:** the audit brief's hypothesis that "new audit diff and payment expiration [features] may not have been verified with PostgreSQL/Testcontainers" — the corresponding Playwright specs (`audit-diff-drawer.spec.ts`, `payment-expiration.spec.ts`) both **passed** in this session's fresh chromium run, and the backend `AuditEventPersistenceTest` (the one PostgreSQL/Testcontainers-backed test touching audit before/after-state) is the one that's currently RED (see TD-1) — so the hypothesis is **partially confirmed**: the audit before/after-state feature does have a real, currently-failing PostgreSQL/Testcontainers-backed test, but the Playwright-level UI feature itself renders fine against its mocked test doubles.
